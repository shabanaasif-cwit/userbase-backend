# v0.2.0

(D) 2026-04-10

### Added

- Reminder list and create responses now include `isRecipient`, indicating whether the authenticated user appears in that reminder’s `recipients` list. Clients can use this to hide per-recipient actions (for example “Mark read”) when an admin can see reminders they were not targeted for.

### Changed

- `PATCH /api/reminders/:reminderId/read` again responds with `{ reminder: … }` containing the sanitized reminder. Callers who are not in `recipients` receive `403` with a clear error instead of a successful response.

### Fixed

- Non-recipient admins no longer get misleading unread state from `myRead` alone when browsing reminders that only target other users; use `isRecipient` together with `myRead` for correct UI behavior.
