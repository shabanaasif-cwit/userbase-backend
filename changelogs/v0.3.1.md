# v0.3.1 — 2026-04-29

(D) 2026-04-29

### Added
- **Refresh-cookie fallback in JWT middleware**: Added silent session-recovery path in `verifyJwt` so protected requests can be re-authenticated from refresh cookie when Bearer access token is missing/expired.

### Changed
- **Refresh cookie scope**: Updated refresh cookie path from `/api/auth` to `/` in `authCookies` so the cookie is available on all protected API routes (including admin/user panel endpoints).

### Fixed
- **Intermittent Unauthorized on active sessions**: Reduced random `401 Unauthorized` responses on notifications/reminders/users panel flows caused by access-token expiry during normal usage.
- **Logout cleanup compatibility**: `clearRefreshCookie` now clears both `/` and legacy `/api/auth` cookie paths to prevent stale cookie state after deployments.

### Security (if applicable)
- **Session continuity hardening**: Protected endpoints now reliably use valid refresh-session context for re-issuing access tokens without forcing immediate re-login.

### Internal
- **Auth middleware alignment**: `src/middleware/verifyJwt.js` and `src/utils/authCookies.js` were updated together to keep token recovery and cookie behavior consistent across routes.
