# v0.2.4

(D) 2026-04-15

### Added

- `uiInteractionLogger` middleware: access-style `INFO` lines per request (listener `host:port`, quoted `METHOD path HTTP`, status, OK/ERR, duration); optional quoted error text on `4xx`/`5xx` when `res.locals.__clientErrorText` is set; JWT success/rejection lines for Bearer requests; auth-oriented lines for login attempt, signup attempt, authenticated user, logout, and refresh.
- `POST /api/client-errors` to accept browser error payloads and emit `[frontend-error]` logs (terminal).
- `POST /api/navigation` so SPAs can report client-side paths for `[navigation]` logs.
- `GET /gallery`, `GET /contact`, and `GET /about` returning a small JSON page marker (`kind: static-route`, `page`, `title`, `status`) so API access logs can reflect static routes when the client calls these URLs.
- OpenAPI coverage for the new endpoints and `StaticRouteResponse`; `ErrorResponse` documents duplicate `message` alongside `error`.

### Changed

- JSON error responses now include `message` with the same string as `error` (existing `error` field unchanged).
- `errorHandler` sets `res.locals.__clientErrorText` before sending JSON so request logs can attach the safe client-facing message without intercepting `res.json`.

### Fixed

- Reliable correlation between failed responses and logged error text by setting `res.locals` in the centralized error handler instead of wrapping `res.json` in the logger.

### Security (if applicable)

- Client error and navigation endpoints are unauthenticated by design (fire-and-forget reporting); payloads are truncated or validated where implemented.

### Internal

- Integration tests extended for error body shape (`error` + `message`), client-errors, navigation, and static page routes.
