# v0.1.1 — 2026-03-25

(D) 2026-03-25

### Added

- Separate **reminders** persistence via `Reminder` model/collection (`reminders`) with recipient read-state tracking.
- Reminder APIs:
  - `GET /api/reminders` — list reminders (users see own; admins can view broader)
  - `PATCH /api/reminders/:reminderId/read` — mark reminder as read

### Changed

- `POST /api/notifications/:notificationId/remind` now creates/stores a **Reminder** (in `reminders` collection) and returns `{ reminder }` (instead of creating a new notification).
- OpenAPI + README updated to document reminders schemas and endpoints and keep docs consistent with runtime behavior.
- Integration tests updated to validate reminder creation + listing through `/api/reminders`.

### Fixed

- —

### Security (if applicable)

- Reminder endpoints require access JWT; admin-only reminder creation remains protected by admin role checks.

### Internal

- Mongo index sync now includes reminders (`Reminder.syncIndexes()`).
- Added `reminderService` + `reminders.routes.js`; removed the `Notification.reminderOf` field so reminders are no longer stored in `notifications`.
