# v0.2.8 — 2026-04-18

(D) 2026-04-18

### Added

- **`uiInteractionLogger`**: `[ADMIN_UI]` lines after the response for notification admin flows—successful **PATCH** `/api/notifications/:id` (including “not updated” when there were no data changes, or listing **updatedFields**), **POST** `/api/notifications/:id/remind` when status is **201**, and **DELETE** `/api/notifications/:id` (delete clicked plus **Notification Deleted** on **204**). Uses `res.locals.__adminNotificationChangedFieldKeys` when set, otherwise falls back to keys present on the PATCH body.

- **`notificationService`**: Helpers to compare persisted vs patched notification state (`sortedIdStrings`, `sortedRoleStrings`, `recipientStateFingerprint`) and **`computeAdminNotificationChangedKeys`** so **`updateNotification`** can report which logical fields actually changed (including **`recipients`** when recipient rows differ).

### Changed

- **`notificationService` `updateNotification`**: Return value is now **`{ notification, changedFieldKeys }`** instead of only the sanitized notification document, so middleware can log accurate field-level updates.
