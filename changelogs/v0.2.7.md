# v0.2.7 — 2026-04-17

(D) 2026-04-17

### Added

- **Notifications (create)**: Separate validation errors for empty or missing `title` (`title is required`) and empty or missing body (`message is required`), with a combined message when both are empty after trim (`title and message are required`).

- **`uiInteractionLogger`**: `inferNotificationPatchNoEffectiveFieldsMessage()` for `PATCH /api/notifications/:id` so access logs can show `No fields are updated` when middleware did not set `res.locals.__clientErrorText`.

- **HTTP integration tests** for login unknown email, missing `@`, missing email/password, signup missing `@`, and logging of notification empty-patch 400s (with `console.error` spy).

- **`notificationPayload` tests** for `targetUsers` / `targetRoles`-only PATCH bodies returning `No fields are updated`.

### Changed

- **Notifications (update)**: “Has something to update” now requires at least one of `title`, `body`, or `targetType` in the JSON body; sending only `targetUsers`, `targetRoles`, or unrelated keys returns **400** with **`No fields are updated`** (replaces `No valid fields to update`).

- **`uiInteractionLogger`**: Responses with status **≥ 400** are written with **`console.error`**; successful lines stay on **`console.log`**. JWT context is appended as a suffix on the main access line (`[JWT userId=… role=…]` or `[JWT unauthorized]`) instead of extra lines for the common cases.

- **OpenAPI**: Login/signup **400** descriptions mention `Email is missing`, `Password is missing`, and `Missing @ symbol` where applicable; signup/login **401** text documents `Incorrect email`, `Wrong Password`, and wrong role.

- **Auth (`authService`)**: Shared string constants for password-format, wrong-password, incorrect-email, missing-`@`, and missing-field messages; `login` uses `assertEmailHasAtSymbol` before missing-field checks.

### Fixed

- **Notification PATCH validation**: Bodies that only touched `targetUsers` / `targetRoles` (or had no effective keys) no longer pass the “has updatable keys” check without changing title, body, or audience type—aligned with `validateUpdateNotificationPayload` semantics.
