# v0.0.0 — 2026-03-20

(D) 2026-03-20

### Added

- Express app bootstrap with centralized config (`env` validation), MongoDB connection, graceful shutdown on `SIGINT`/`SIGTERM`, and structured error handling (`AppError`, async route wrapper, 404 handler).
- Health route `GET /health` with Mongo connectivity status (`503` when DB unavailable).
- User model (`email`, `passwordHash`, `role`, `accountStatus`, timestamps).
- Authentication: `bcryptjs` password hashing; JWT access token (Bearer) and refresh token (httpOnly cookie, path `/api/auth`); refresh sessions stored in MongoDB (`RefreshToken` with `jti`, rotation, revocation, TTL index).
- Auth routes: `POST /api/auth/signup`, `POST /api/auth/login`, `POST /api/auth/refresh`, `POST /api/auth/logout`, `GET /api/auth/me`.
- `verifyJwt` middleware attaching `userId` and `role` from access JWT.
- Strict HTTP method handling for auth paths (`405` + `Allow` header when method does not match).
- API documentation: OpenAPI spec at `GET /openapi.json`, Scalar UI at `GET /docs`.
- Security baseline: Helmet (including CSP adjusted for Scalar CDN), CORS with credentials and configurable `FRONTEND_ORIGIN`, `trust proxy` in production.

### Changed

- Project entry split into `src/index.js` (process lifecycle) and `src/app.js` (Express wiring).

### Fixed

- Blank Scalar docs page caused by default CSP blocking external scripts; resolved by explicit CSP directives for Scalar assets.

### Security (if applicable)

- Refresh token delivered as httpOnly cookie (`Secure` in production, `SameSite=lax`); separate secrets for access vs refresh JWTs via environment variables.

### Internal

- Dependencies: `express`, `mongoose`, `dotenv`, `cors`, `cookie-parser`, `helmet`, `bcryptjs`, `jsonwebtoken`, `ms`, `@scalar/express-api-reference`.
