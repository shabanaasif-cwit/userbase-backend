# v0.1.6 — 2026-04-04

(D) 2026-04-04

### Added

- HTTP integration coverage for reminders when the source notification uses `targetType` `user` or `admin`.

### Changed

- Reminder `targetType` is limited to the same four values as notifications: `users` (specific ids), `user` (all app users), `admin` (all admins), and `all` (everyone). The legacy `role` value was removed from the Reminder schema and from reminder recipient resolution.
- OpenAPI descriptions for notification create/update bodies now state that recipients are chosen only via those four `targetType` values; `targetRoles` on the request is optional and ignored.
- README: `POST /api/notifications` bullet updated to describe the four `targetType` options.

### Fixed

- Creating a reminder from a notification with `targetType` `user` or `admin` now resolves recipients correctly (same rules as notifications) instead of failing with an invalid `targetType` error.

### Internal

- `reminderService` recipient resolution no longer accepts a `targetRoles` argument; persisted reminder `targetRoles` continues to mirror the inferred roles from `user`, `admin`, and `all` targets.
- Notification payload and HTTP integration tests updated for validation copy and for a valid non-admin “create notification” body in the RBAC case.
