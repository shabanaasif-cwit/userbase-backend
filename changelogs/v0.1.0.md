# v0.1.0 — 2026-03-24

(D) 2026-03-24

> **Scope:** Builds on [v0.0.0](./v0.0.0.md) (auth, JWT, `verifyJwt`, baseline `User` stub). **Today’s work** centers on the **user domain** (roles + account status in the data model) and **admin-only user APIs**, plus notifications, validation, tests, and doc/error alignment. Existing JWT + role middleware is reused; only **403** message text was standardized for docs.

### Added

- **Users, roles, and account status (data model)**  
  - **`User`** collection: `role` enum **`user`**, **`accountStatus`** **`active` | `deactivated`** (with timestamps).  
  - **`AdminUser`** collection: same email/password pattern; **`role`** fixed **`admin`**; same **`accountStatus`** enum.  
  - Supports separating end-user accounts from admin accounts while keeping a consistent status field for gating (e.g. login / `GET /api/auth/me`).

- **Admin-only user APIs** (`verifyJwt` + `requireRole("admin")`)  
  - **`GET /api/users`** — list with **pagination** (`page`, `limit`) and **filters**: `role`, `accountStatus`, **`search`** (email-oriented).  
  - **`PATCH /api/users/:userId`** — update profile fields (**`email`**, **`role`**, **`accountStatus`**) including promoted flows (e.g. user → admin) handled in `userAdminService`.  
  - **`PATCH /api/users/:userId/deactivate`** — deactivate an account.  

- **`GET /`** — API info alongside health and auth.

- **Notifications (separate feature area)**  
  - **`Notification`** model (recipients, targeting, indexes synced in `connect.js`).  
  - Routes: admin **create** / **update** / **delete**; authenticated **list** + **`PATCH .../read`**; targeting by user ids or roles.  
  - **`src/validation/notificationPayload.js`**; OpenAPI notification schemas; **`npm test`** coverage (integration + validator unit tests).

### Changed

- OpenAPI / README: document user admin routes and notification routes; global error shape, invalid JSON, admin **403** descriptions; signup/login **400** notes for malformed JSON.
- **403** JSON body for failed role checks: `Forbidden (admin only)` (aligned with docs).

### Fixed

- Malformed JSON bodies return **400** `{ "error": "Invalid JSON" }` via centralized error handling.
- Mongoose cast errors mapped to **400** `Invalid id` where applicable.

### Security (if applicable)

- Admin user routes require valid access JWT **and** `admin` role; same baseline as v0.0.0 for token handling and cookies.

### Internal

- `userAdminService` implements list/filter/update/deactivate logic; `asyncHandler` on new routes; README ↔ OpenAPI kept in sync for endpoints.
