# v0.2.6 — 2026-04-16

(D) 2026-04-16

### Added

- **Auth errors**: Distinct client messages for common login/signup cases — missing email (`Email is missing`), missing password (`Password is missing`), email without `@` (`Missing @ symbol`), unknown email (`Incorrect email`), bad password (`Wrong Password`), and a shared constant for the password number/special-character rule.

- **Signup**: Validates `@` in the email before other checks so malformed addresses return `Missing @ symbol` (400).

- **HTTP integration tests** covering the new login/signup responses (including unknown email and missing-field cases).

- **`uiInteractionLogger`**: `normalizedPathname()` for stable path matching; recognition of `/auth/login` and `/auth/signup` in addition to `/api/auth/*`; exported `isAuthSignupPath` and `inferLoginValidationMessage` for reuse; inferred client error text on 400 when `res.locals.__clientErrorText` is unset (login/signup validation).

### Changed

- **Login** (`authService.login`): No longer appends a default domain to emails missing `@`; behavior is now a 400 with `Missing @ symbol` (aligns signup/login).

- **401 responses**: Replaced generic `Invalid credentials` with `Incorrect email` when no user/password hash exists, and `Wrong Password` when bcrypt does not match.

- **400 responses**: Replaced combined `Email and password required` with separate `Email is missing` / `Password is missing` where applicable.

- **OpenAPI** (`openapi.js`): Login and signup operation descriptions for 400/401 updated to list the new error messages.

- **UI logs**: Login/signup `INFO` lines log missing email, missing `@`, or missing password where relevant; completion line includes inferred validation text for 400s on auth POSTs.

### Fixed

- **Auth logging under proxies or alternate mounts**: Path detection uses `originalUrl` (with fallbacks) so login/signup logging and error inference match the real route.

### Security (if applicable)

- **Login input handling**: Removed silent rewriting of emails without `@` (previously suffixed with a fixed domain), which could confuse clients and obscure invalid addresses.

### Internal

- Centralized repeated auth error strings and password-format message in `authService` constants; small helper `assertEmailHasAtSymbol`.

- Integration test for duplicate signup now expects the current duplicate-email copy (`That email is taken. Try another.`) instead of the older `Email already registered` wording.
