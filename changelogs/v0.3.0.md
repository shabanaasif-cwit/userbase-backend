# v0.3.0 — 2026-04-28

(D) 2026-04-28

### Added

- **Access-token renewal response header**: Protected API responses now include **`X-New-Access-Token`** (via JWT middleware) so clients can rotate access tokens during normal authenticated requests.

### Changed

- **Single active refresh session policy on login**: Login now checks for an active refresh session. If another browser/device session exists and the request does not include that session's valid refresh cookie, it returns **409** with **`Session is already logged in.`**.

- **Same-browser re-login behavior**: When the request includes the same valid refresh cookie, login revokes prior active refresh tokens for that user and issues a fresh session.

- **CORS exposed headers**: App CORS config now exposes **`X-New-Access-Token`** so browser clients can read renewed access tokens from responses.

- **OpenAPI login docs**: Added documented **409** response for **`POST /api/auth/login`** explaining active-session conflict and same-browser resolution path.

### Fixed

- **Auth flow consistency**: Login route now passes incoming refresh cookie context to auth service, enabling expected session-conflict handling for multi-client logins.

### Security (if applicable)

- **Session hardening**: Reduces parallel authenticated sessions across different clients by rejecting concurrent login attempts without the active session cookie.

### Internal

- **Integration coverage**: Added HTTP integration tests for:
  - second login without refresh cookie while a session is active returns **409**,
  - same-browser login with persisted cookie succeeds.
