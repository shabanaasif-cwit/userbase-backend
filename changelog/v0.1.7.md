# v0.1.7

(D) 2026-04-06

### Added

- Admin endpoint `PATCH /api/users/:userId/toggle-account` to flip `accountStatus` between `active` and `deactivated` in one request (for activate/deactivate UI without branching on current status).
- `toggleUserAccountStatus` in the user admin service (regular and admin users, same lookup pattern as deactivate).
- OpenAPI documentation for the toggle-account route.
- `src/utils/email.js` with `assertNonEmptyEmailLocal`: signup, login, and admin user email updates reject an empty local part (the segment before `@`).
- HTTP integration test: admin toggles a target user off then on via `PATCH .../toggle-account`.

### Changed

- README: documented the toggle-account route in the API list.
- README: `FRONTEND_ORIGIN` example port updated from Vite default `5173` to `3000`.
- `authService`: validate non-empty email local part on signup and login (after optional login domain suffix).
- `userAdminService`: validate non-empty email local part when an admin updates `email`.

### Fixed

- Admin email updates could accept addresses with no local part (e.g. `@example.com`); they are now rejected consistently with explicit validation.

### Security (if applicable)

- Stricter email validation on auth and admin paths reduces acceptance of malformed or ambiguous addresses.

### Internal

- `users.routes.js`: wired `PATCH /:userId/toggle-account` with admin-only middleware and `methodNotAllowed` for non-PATCH methods.
